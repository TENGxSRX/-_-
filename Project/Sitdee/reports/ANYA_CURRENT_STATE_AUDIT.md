# ANYA — Full Current-State Audit

Audit date: 2026-09-23 (Asia/Bangkok)  
Scope: read-only repository, local artifacts and bounded focused tests. No camera/RTSP was opened, no dependency was installed, and no model was trained.  
Evidence labels: `[CURRENT REPO]`, `[CURRENT FILE]`, `[TESTED NOW]`, `[HISTORICAL REPORT]`, `[NOT VERIFIED]`, `[BLOCKED]`.

## 1. EXECUTIVE_SUMMARY

- [CURRENT REPO] This is a substantial engineering/research prototype: it can read file/webcam/RTSP sources, detect people with YOLO/ByteTrack, collect anonymous per-track pose evidence with MediaPipe, enforce padded-crop safety, run optional experimental posture classifiers, and write bounded session telemetry/reports. Several live and multi-hour runs have saved artifacts.
- [CURRENT FILE] The only current five-class model trained from explicit project Human Ground Truth is `webcam_p001_fiveclass_exp_v1`, trained from 257 observations by one participant (P001), two nonempty sessions and 30 segments. Its untouched same-person/session holdout macro-F1 is 0.8902 on 45 observations/five segments. This is promising pilot evidence, not independent-person or multi-person CCTV generalization.
- [CURRENT FILE] MultiPosture V1/V2 models were trained on a verified landmark CSV with subject-grouped evaluation; they are source-domain keypoint models, not proven RGB/CCTV-compatible classifiers.
- [CURRENT FILE] DriveNet v6 supports the frozen RGB-native V4 two-class TUP/TLB pilot. This is a narrow source-domain experiment; it does not validate five classes or office CCTV generalization.
- [CURRENT REPO] PoseV2Stage itself produces pose/landmark/feature evidence and telemetry; it is not a posture classifier. It is off by default in the autonomous long-session runner and does not call V4. A separate explicit upper-body runner can feed compatible six-feature evidence into an experimental classifier. The webcam P001 five-class option is opt-in and not the production default.
- [CURRENT FILE] The `data/controlled_cctv_v2` directory contains a real RTSP collection attempt with 27,077 event records, but `accepted_samples_this_session=0`, root sample CSV has zero rows, and all event labels are null/`NOT_ASSIGNED`. It is runtime/tracking telemetry, not labeled training data.
- [HISTORICAL REPORT] A 3 h 51 min anonymous tracking session, a one-hour V4 demo session and a ten-minute unlabeled CCTV feature-pool session completed. These establish that the software can run for meaningful periods under specific conditions. They do not establish reliable physical identity continuity, posture accuracy, or indefinite service reliability. The one-hour session contained 8,533 source failures, 3 reconnects and high latency tails.
- [TESTED NOW] 52 focused tests passed. The full repository suite was not run. No physical camera was accessed during this audit.
- [CURRENT REPO] **Readiness judgment:** suitable as a research prototype and for carefully supervised, controlled pilots. Evidence is insufficient for unattended continuous real-room monitoring or claims of general multi-person posture accuracy. Runtime reliability and classification accuracy are separate: session infrastructure has useful evidence, while identity continuity and posture generalization remain unproven.
- [CURRENT REPO] Main blockers are (1) no multi-participant, multi-session, multi-view CCTV Human GT; (2) no human-verified per-person tracking continuity during crossings/occlusion; (3) limited human-labeled CCTV sample collection despite the collector existing; (4) one-participant training/evaluation for the five-class webcam experiment; and (5) weak evidence for safe uncertainty behavior across new people/views.

- **Why now:** [CURRENT FILE] `data/controlled_cctv_v2` currently has 0 accepted labeled rows, the learned webcam model is one-person/one-domain, and ByteTrack has no human-verified crossing evidence. Training now would either lack target examples or inherit identity leakage.
