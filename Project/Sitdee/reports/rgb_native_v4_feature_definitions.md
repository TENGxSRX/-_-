# RGB-native V4 feature definitions

## Frozen input contract

The source frame is processed by the pinned MediaPipe Pose Landmarker task. V4 uses the 33 World Landmarks (`x`, `y`, `z`) and the five core landmarks `nose`, `left_shoulder`, `right_shoulder`, `left_hip`, and `right_hip`. Coordinates are copied and translated by

`h = (left_hip + right_hip) / 2`

`p_centered[i] = p_world[i] - h`

No arbitrary axis flip, mirror, or fitted external-label transform is applied.

## Feature families

- `world` — 15 centered XYZ values in fixed landmark/axis order.
- `normalized_world` — the same 15 values divided by the L2 norm of the centered shoulder midpoint. This is a V4 scale-invariant experiment, not a claim about MultiPosture preprocessing.
- `geometry` — 15 deterministic features: trunk inclination, normalized trunk vector, shoulder/hip line angles, shoulder/hip asymmetry, shoulder-to-hip distances, nose-to-shoulder offsets, neck inclination, and torso length.
- `hybrid` — `world` followed by `geometry`, 30 values.

All feature names are generated by `src/posture_ai/features/rgb_native_v4.py`; inference rejects any different feature count or order.

## Visibility rule

Image-landmark visibility is used as the quality gate for the five core points. A sampled frame is accepted only when all five visibility values are finite and at least `0.5`, and World Landmark coordinates are finite. Low-quality coordinates are not imputed or silently clipped.

## Scientific boundary

V4 is currently a source-domain pilot with `TUP` and `TLB` only. It does not provide labels for `TLF`, `TLL`, `TLR`, or `SLOUCH`, and therefore cannot replace the five-class MultiPosture direction model yet.
